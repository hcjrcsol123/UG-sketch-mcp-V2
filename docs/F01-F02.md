
# V2 F01/F02：平面草图与空间基准面

F01/F02 已实现并通过本机 NX2506 验收：任意空间平面、既有平面面和基准面上的草图，以及按空间位置/方向建立原生基准面。长度毫米、方向无量纲。本页保留这两项的接口；后续图元扩展见 F06.md。

## 原生空间基准面

新增 `nx_prepare_datum_plane`，明确输入世界坐标原点、法向和面内 X 方向：

```json
{
  "operation_id": "datum-prepare-1",
  "ownership_id": "<current owner>",
  "binding_epoch": 1,
  "revision_id": "<current revision>",
  "origin_mm": [10, 20, 30],
  "normal": [1, 1, 1],
  "x_axis": [1, -1, 0]
}
```

这是原生 DatumPlane 特征。成功执行后返回 `datum_plane_id`，使用该标识在基准面上建立草图；零件检查的特征清单提供原生位置、法向及面内坐标系读回。

## 任意平面草图

扩展既有 `nx_prepare_sketch`。以下为任意空间平面的空草图：

```json
{
  "operation_id": "sketch-prepare-1",
  "ownership_id": "<current owner>",
  "binding_epoch": 1,
  "revision_id": "<current revision>",
  "origin_mm": [10, 20, 30],
  "normal": [1, 1, 1],
  "x_axis": [1, -1, 0],
  "geometries": []
}
```

`geometries` 可以省略或为空；若填写，坐标为草图局部二维毫米坐标。例如：

```json
[{"id": "line1", "type": "line", "start_mm": [0, 0], "end_mm": [12, 0]}]
```

不同定位方式互斥，公共会话/修订字段相同：

| 定位方式 | 输入 |
| --- | --- |
| 世界坐标系 | `origin_mm`、`normal`、`x_axis` |
| 既有基准面 | `support_datum_plane_id`、`x_axis`，可选 `origin_mm`，缺省为基准面原点 |
| 既有平面面 | `support_face_id`、`origin_mm`、`x_axis`，可选 `support_body_id` |
| 原有主平面 | `plane` 为 XY/XZ/YZ，`origin_mm` |
| 原有面选择方式 | `support_face_selector`，可选 `support_body_id` 和 `face_origin_offset_mm` |

基准面和面的法向从实际支撑对象读取。指定的原点须位于支撑平面。空间法向被归一化，X 方向投影到平面后归一化，Y 方向由 `normal × x_axis` 确定；零法向或平行于法向的 X 方向不能定义有效坐标系。

查找倾斜面时，调用 `nx_query_faces`，传入 `selector="all_planar"`；从候选记录的 `face_journal_id` 选择目标。这一步枚举实际平面面，不自动替用户选择第一张面。

基准面与面上的草图使用原生 Coincident Plane 支撑关联；不能仅凭用户属性判断关联成功。NX 的外部草图可通过内部草图特征依赖基准面，因此回读同时提供直接父对象和 `ancestor_feature_ids`，沿实际 GetParents 依赖链检查基准面。查看草图坐标系和支撑对象，并在保存重开后检查其保持情况。

## 执行与验证

保留现有 prepare/execute/verify 流程：

1. 准备操作返回操作记录；完成后取得 `result.plan.plan_id`。
2. 使用 `nx_execute_plan` 执行该计划，必要时查询 `nx_get_operation`。
3. 使用 `nx_verify_part`，传入成功执行的 `execute_operation_id` 独立回读。
4. 保存副本模式可使用 `nx_save_copy`，须 `reopen=true`；成功后使用返回的新所有权与绑定凭据。

源码构建仍使用 `tools/build-m2-bridge.ps1`。新增实际 NX 验收入口位于 `tests/nx/v2/`：先编译 `build-acceptance.ps1`，再通过本机 `run_journal.exe -nx tests/nx/v2/RunAcceptance.py` 调用编译好的 C# 生产适配器验收。这是测试入口，不代表本批新增了产品 Journal 工具。

`tools/v2/f01_f02_mcp_client.py` 将一组请求自动串接为 prepare/execute/verify；输入文件中写入当前接管凭据、revision_id 和 steps，运行时使用 `--request <请求文件> --config <本机配置> --output <结果文件>`。它不自动接管。可选 save_copy 会保存并重开，后续工具须采用保存结果返回的新所有权与绑定凭据。

安装前应正常关闭本项目的 NX 会话，避免替换已加载 DLL。无哈希安装使用更新后的 `tools/install-local.ps1`，通过已安装 MCP 的实际版本和工具发现记录结果，不重启计算机或 Codex。
