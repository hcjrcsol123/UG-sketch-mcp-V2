
# F04 角度基准面

## 输入与方向

传入有限的 `angle_deg`、`axis_line_id`，以及二选一的 `support_datum_plane_id` / `support_face_id`。角度单位为度，范围 [-180, 180]，包含零和两个端点。不传外部 `mode`，不混入 `distance_mm`、`origin_mm`、`normal` 或 `x_axis`。F02 固定平面和 F03 距离法保持兼容。

```json
{
  "operation_id": "f04-prepare-1",
  "ownership_id": "<current owner>",
  "binding_epoch": 1,
  "revision_id": "<current revision>",
  "support_datum_plane_id": "<native datum feature ID>",
  "axis_line_id": "<existing Line journal_id>",
  "angle_deg": -30.0
}
```

角度按实际直线的 StartPoint → EndPoint 方向使用右手规则旋转参考平面法向；反转直线端点即反转轴方向。轴必须是当前零件中非退化、位于参考平面内的原生 `NXOpen.Line`，包括已有草图线。当前 F04 不扩展到 Edge、DatumAxis 或任意坐标轴输入，也不提供 F20 空间曲线创建。

先通过 `nx_inspect_sketch` 读取已有草图 `geometry` 中 `kind="LINE"` 的 `journal_id`。若没有合适的线，可用已有 F01 在参考面上创建含一条线的草图，再检查返回的草图。Face ID 使用 `nx_query_faces(selector="all_planar")` 返回的 `face_journal_id`。对象标识与当前模型修订绑定；新增几何可能使 NX 的实体 JournalIdentifier 重编号，修改模型后应重新查询，不能长期缓存。

## 原生实现与回读

实际 API 路径为 `DatumPlaneBuilder.GetPlane → SetMethod(Angle) → SetGeometry([reference,line]) → SetExpression → SetAlternate(One) → Evaluate → CommitFeature`。本机 NX2506 探针表明原生 Angle 表达式正号与上述右手规则相反，生产按 `native expression = -angle_deg` 换算。原始表达式值和右手几何角分别记录，不把表达式符号隐藏或改写为用户输入。

准备阶段只生成计划，不创建特征；执行前复核轴的实际对象和端点。执行后独立读取原生 Angle 方法、角度表达式、参考平面和轴的 `Plane.GetGeometry()`、参考特征的父关联，以及实际法向的旋转和轴的平面距离。独立直线未必有父 Feature，不能要求它出现在 `GetParents()` 中；轴关联由原生 Geometry 对象确认。

原生参数、轴端点、参考对象、几何和关联进入模型检查、修订跟踪及保存重开比较。生成的 `datum_plane_id` 可继续供 F01 草图使用。保存重开会更新所有权和绑定凭据，后续调用使用 `nx_save_copy` 返回的新值。
