# F21 扫掠

## 目标与边界

在当前独立毫米工作部件中，以显式草图截面和空间曲线路径建立 NX 原生关联扫掠特征。覆盖单路径和连续曲线链、明确实体或片体输出，以及本机 NX2506 实际可用且能回读验证的方向和扭转控制。导引曲线按原生接口证据决定是否纳入，不能把未验证 API 当作已交付能力。

长度 mm，角度 deg，方向无量纲。输入对象必须来自当前会话及修订，修改后重新查询；不依赖跨会话 Tag 或永久不变的 JournalIdentifier。扫掠只创建新输出，不默选布尔目标，不引入装配、WAVE 或 Teamcenter。以下支持域不等于全部输入构型均已实测。

| 要求 | 可核对的接受依据 |
| --- | --- |
| R21-1 原生关联 | 原生 Swept 特征及输出，真实截面、完整有序路径和原生选择规则；不能用离散复制或拉伸冒充扫掠 |
| R21-2 路径和输出 | 单路径与连续链代表案例，明确 solid / sheet，严格拒绝缺失、重复、断开、歧义或不支持的输入 |
| R21-3 方向与扭转 | 原生实际控制定义回读，非对称轮廓的端部及中间几何独立验证，证明控制实际生效 |
| R21-4 几何证据 | 类型、完整结果集合、适用的边面几何、截面位置和方向；体积与包围盒只作辅助，不能单独证明正确 |
| R21-5 生命周期 | prepare 无变更、所有权和修订检查、execute/get、fresh 原生篡改负控、实际提交后故障 Undo 恢复、未知停写 |
| R21-6 保全与持久化 | 非空旧草图、空间曲线、实体、特征及表达式保全，旧 Sweep 定义保全，SaveCopy 关联核对，新会话独立重开 |

## 接口与系统边界

入口 `nx_prepare_sweep`，复用 prepare → execute → operation.get → 显式 fresh 验证、同一事务 Undo、inspect/revision 和 SaveCopy。Python host、C# 公共契约与公共路由由 systems-integration 统一，工厂不另建通信、线程或所有权路径。

所有字段必填：`operation_id`、`ownership_id`、`binding_epoch`、`revision_id`、`sketch_id`、`path_curve_ids`、`profile_output`、`orientation_mode`、`twist_angle_deg`。`profile_output=solid|sheet`；路径为 1—32 个唯一、有序、当前修订的独立 Line／Arc ID；角度有限且在 [-90, 90] deg。路径编辑或新增几何可能重排 JID，应重新 inspect，不跨会话复用 Tag。

首版只接受一条连通的 active Line 截面，最多 256 个顶点；solid 为闭合多边形，sheet 可为开放或闭合折线，reference 曲线不进入截面。路径从 Sketch 原点出发，该点必须是唯一截面顶点；每个 active 顶点相对该点的偏移与初始单位切向点积绝对值须 ≤1e-6 mm。单 Line 不唯一确定截面平面，不能将此条件描述为所有情况下 Sketch 平面法向都等于切向。各路径段端点以 1e-6 mm 判连接，切向向量差限 1e-7；闭合、退化、分支或不连续路径拒绝。首版没有额外导引曲线、Spine、缩放或布尔合并。完整支持限制及原生回读见 [API 记录](F21-api-notes.md)，允许的输入数量不表示上限性能或所有构型已经实测。

截面与路径成为真实关联输入，会影响特征父子关系、源几何保存、重开匹配及 stale 判定。方向向量与扭转角必须有确定坐标系和符号语义；链的顺序和行进方向必须确定。不支持的路径连接或轮廓形式应在无模型变更的阶段明确拒绝。

探针发现 NX 原生线性角度规律的正角与此方向相反，因此产品内部须作反号映射，并同时记录请求值与原生实际值；单一探针不能代替产品和保存重开验收。路径各段的真实有向端点、顺序和连接需要读回，不能只检查输入 Tag 集合。原生连接容差与独立几何后验限分别记录，不把 builder 连接容差当作输出精度保证。

方向模式为 `transport` / `linear_twist`，分别映射 NX `Fixed` / `ByAngularLaw` 的线性规律。`transport` 的 `twist_angle_deg` 必须为零；它沿弯曲路径输运截面，不表示世界姿态不变。后验在有限站位对照累计弧长理想规律并限差，不能宣称原生整段严格按弧长线性。

草图支撑限制为本机已证的内部 DatumCsys 构型：真实 XY DatumPlane 附着、8 实体、CSYS→Xform→Direction／Scalar／Plane／Point 四父闭图。三个常量叶对象与无父、无表达式、Method=Undefined 的 Plane 均严格回读，坐标系、组件和 Sketch frame 必须一致。共享读取沿实际 Tag 依赖取得真实支撑 Plane，完整来源进入修订与持久化投影；未知构型不能根据共面性猜测关联，也不能当作 WORLD_FRAME。

原生设置为 G0=0.001、G1=0.5，明确启用 PreserveShape。原 G0=0.01 的弯曲链出现 0.028709 mm 首差并已证回滚；单变量降低 G0 后，新直线／弯曲链样本通过，弯曲链产品 120 个站位点最大残差约 0.008682 mm，产品门限始终保持 0.01 mm。本机随附文档仅称 Position／Tangent tolerance，未确证这两个属性的单位，不把 G1 标为 deg，也不将这组样本推广为一般因果或误差界。产品对端点／连接使用 1e-6 mm，截面边与内部有限边面采样使用 0.01 mm；每段包含多个内部截面与各侧面内点，检查完整边面邻接和端盖。独立验收另用预置的 0.02 mm／0.01 rad 内部样点限，数值语义及支持边界见 [API 说明](F21-api-notes.md)。它们是有限位置的判据，不是整个曲面误差界、制造精度或任意扫掠的数学证明。

Section 输出曲线的 JID 可随新增 Swept 重排。仅在完整 LINE、原生规则／源关联、计数／索引和 1e-6 mm 域匹配双向恰一成立时，对两处 `section_output_jid` 作局部比较投影；其他定义、源身份组合、路径方向／端点、参数和完整几何仍严格，保留原始读回及 before→after 输出 ID 映射。不全局忽略 JID，不宣称未采集的输出 Tag 或对象生命周期。snapshot／revision、fresh、Undo 与持久化写前检查使用一致规则。

r04 的 sweep prepare 在登记并尝试排队后立即返回实际记录，正常为 QUEUED，排队失败可为 FAILED；须只轮询已确认的 operation ID，成功取得 plan 后才执行。Python verify 初响或操作轮询结果不确定会保持本地 UNKNOWN 拦截，读到终态也不会自动解锁。实际 installed 七组在原 5 秒 transport 配置下完成，未靠扩时掩盖初响缺陷；大模型／全部输入域的性能未验证。

跨能力决策：工作零件含任何 `SKIN` / Swept 时，旧建模和编辑写入口保守拒绝。F21 自身通过显式例外执行严格定义及几何保全，SaveCopy 走严格读回核对；inspect、operation.get、fresh 和安全所有权归还不因这项写门控被禁用。应在创建首个扫掠前建立所需草图、路径等输入。此轮不扩展旧能力对任意 Sweep 历史的保全，不为此重跑旧功能矩阵。

建议先准备全部独立空间曲线，再建立草图，最后扫掠。正式夹具改为原生 API 一次预建输入并按当前 inspect 唯一定位，不能据此宣称所有旧工具可以任意顺序组合。

风险包括路径拐角或闭环奇异、截面自交、意外封口、方向翻转、角度单位及符号错误、读原生定义的 getter 副作用，以及旧输入 JID 重排导致错误身份匹配。

## 验证边界

未穷举其他姿态、负角组合、极限数量和尺度、复杂旧特征混合、运行中断连、失败 Undo 或其他 NX 版本。`SweptBuilder` 已被 NX 标记为 deprecated，未来版本兼容需另行验证；旧 G0=0.01 模型可能被严格拒绝，不自动迁移。UNKNOWN 不重放、不自动解冻。
