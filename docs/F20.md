# F20 空间直线、圆弧与圆

## 目标与边界

在当前独立毫米工作部件中创建世界 XYZ 独立原生 Line 或 Arc，不归属草图。支持直线、圆心／法向／面内零角方向／半径／起止角圆弧、经过三个显式点的圆弧，以及完整空间圆。复用所有权、修订、prepare → execute、operation.get、显式 fresh 验证、事务 Undo 和 SaveCopy 生命周期。长度 mm，角度 deg，方向无量纲。

中心定义必须明确面内零角方向，以使任意空间平面的角度语义确定；不静默归一化非法方向。三点定义必须确定经过中间点的弧段，不能仅验证三点落在同一圆上。输入退化、非有限值、模式混用及超出明确数值域者拒绝。


| 要求 | 可核对的接受依据 |
| --- | --- |
| R20-1 原生空间曲线 | 四种输入路径实际生成工作部件的独立 Line／Arc，实际 Sketch membership 为空；单位及输入语义可追踪 |
| R20-2 有向几何 | 非轴向线、偏心倾斜平面弧、三点优弧和整圆的真实类型、世界样点、平面、半径、长度／扫角独立核对 |
| R20-3 严格输入 | 模式互斥、必填项、有限数、单位方向、正半径、非零线／扫角、重复或共线三点及数值域在 Python 与 C# 边界拒绝 |
| R20-4 模型生命周期 | prepare 无变更；既有非空曲线及模型保全；外部曲线编辑影响 revision／stale；fresh 实读；真实提交失败 Undo 恢复，未知保持停写 |
| R20-5 持久化与安装 | 独立曲线进入 inspect／revision 和 SaveCopy 重开比较；installed 真实 transport，保存模型在新 NX 会话独立只读核对 |

## 接口与几何判据

入口 `nx_prepare_spatial_curve`。共同必填 operation_id、ownership_id、binding_epoch、revision_id、curve_type；四个互斥字段组见 [API 记录](F20-api-notes.md)。`arc` 必须显式 definition_mode=center 或 three_points；line／circle 不传 definition_mode。

后验须取得真实原生类型、世界端点、圆心／半径／平面与方向、弧段长度及多个内部样点，并独立对照输入定义；仅数量、包围盒、半径或端点不能证明弧段正确。既有曲线、草图、实体、特征、表达式和辅助对象的保全及恢复必须有证据。

风险包括近退化三点的数值病态、相同圆上错误弧段或相反手性、隐式草图附着、曲线被旧快照遗漏，以及 NX 读回／清理的不确定状态。支持域和容差须按实际实现及样本明确；数值阈值不等于制造精度保证，不主张其他 NX 版本或一般复杂旧特征组合已验证。

建模后验对中心、端点、半径及弧中点使用 1e-6 mm，法向分量／扫角使用 1e-7 数值限。独立验收另以真实 UF 参数区间五点求值核对整段点序和长度，mm限1e-6、角度限1e-7 rad；负向大弧、三点优弧及三维倾斜整圆有实际样本。

## 对象身份与持久化

NX 在追加同类独立曲线时可能重新分配旧 JournalIdentifier；产品以同会话同 Curve 对象、Tag、完整原生几何签名及数量严格保全，输出逐旧对象 `prior_curve_identity_map`。JID 不作为不可变身份，操作后必须重新 inspect 当前修订的 `spatial_curves`，不可把旧 JID 指向的当前对象当作旧对象。Tag 仅当前 session 有效。

空间曲线进入 inspect／语义快照，外部编辑会推进 revision 并使旧计划返回 STALE_PLAN。活动草图时 prepare 返回 NX_BUSY，不隐式把空间曲线加入草图。

SaveCopy 仅接受具备完整读回、几何可唯一分辨的独立 Line／Arc；未知类型或重复／近重复几何在 SaveAs 前保守拒绝。跨重开按完整类型／几何一对一匹配，不依赖 Tag、JID 或排序，返回 before_id→after_id 映射。当前持久化比较沿用共享语义比较器：数字字符串坐标／法向逐分量容差 max(1e-7,1e-9×max(abs(a),abs(b)))；原生 double 半径与起止弧度精确比较，其余字段精确。此 SaveCopy 容差在大坐标下可大于建模后验限，不能据此宣称全输入数值域的 1e-6 mm 保存精度。
