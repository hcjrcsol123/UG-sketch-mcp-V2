# F21 NX API notes and development evidence

## Final recorded status

F21 prepare registers its known operation ID, attempts dispatch, and returns the actual record under the lifecycle lock: normally `QUEUED`, or `FAILED` when queueing fails. Pending records use the operation-status API. An unknown outcome remains sticky for the local client even if a later record is terminal; it does not automatically unfreeze writes. A lost or malformed response is not proof of cancellation. Original UNKNOWN operations and sessions are retained, not replayed or automatically unfrozen, and later evidence does not establish their recovery.

The independent reopen reader has a narrow **reader-only state-audit** exception for planar UV limits: at most eight binary64 steps, with both the more conservative derivative bound and corresponding world-point difference at most 1e-9 mm. It checks finite, ordered, nondegenerate mappings anchored to the recorded native plane and compares world points even when UV is unchanged; all other inventory fields and nonplanar UV remain exact. This is not a production geometry tolerance. The original reopen UNKNOWN remains unchanged.

Installation uses PowerShell 7 (`pwsh`), as specified in the project README. The user cancelled the earlier shutdown request; do not shut down or restart the computer. Units are millimetres and degrees unless otherwise stated.

## Historical development observations

The observations and probes below are preserved at their original stages. Any historical “pending” or “requires validation” statement describes that earlier point, not the final recorded status above. Individual API probes are not themselves product acceptance evidence.

The local NX 2506 `Features.FeatureCollection.CreateSweptBuilder(Swept)` exposes `SectionList`, `GuideList`, `BodyPreference`, `OrientationMethod`, and `G0Tolerance`/`G1Tolerance`. A whole-Sketch `CurveFeatureRule` is used for the profile and a single `CurveDumbRule` for the ordered, independent Line/Arc path. `SectionData.GetRules`, `CurveDumbRule.GetData`, and `SectionElementData.GetSectionElementData1` provide the native rule, members, and oriented endpoints. Section element enumeration itself is not path order: the measured Line–Arc example returned Arc first; connectivity and the explicitly chosen starting endpoint determine the chain. `SweptBuilder` is deprecated in the NX 2506 headers since NX 2412, with `SweptBuilder1` designated as its replacement; future-version compatibility is not established.

The public candidate uses `orientation_mode` values `transport` and `linear_twist`. They map to native `Fixed` and `ByAngularLaw` with a linear 0-to-end rule, respectively. `transport` requires zero twist. The public signed angle is right-handed about the path's forward tangent; the measured native end expression uses the opposite sign. The factory requires degree expressions and currently accepts explicit angles in −90° to +90°. A 5 mm Line followed tangentially by a quarter-circle of radius 10 mm with a 45° right-handed twist showed intermediate angles near a linear function of accumulated length. This is a finite probe of an approximated NX surface, not a guarantee of exact arc-length interpolation for every supported shape. Production geometry verification checks bounded interior stations and rejects results exceeding its recorded tolerance.

The local default builder had `G0Tolerance=0` and `G1Tolerance=0`; `Validate()` nevertheless returned true and `CommitFeature()` failed with `Unable to approximate guide string`. Setting G0 to 0.01 and G1 to 0.5 allowed the sampled operations to commit. The installed `NXOpen.xml` describes them as position and tangent tolerances respectively but does not state their units; G1 must not be represented as a proven degree value. The independently defined product interior sample limit is 0.01 mm, a measurement threshold rather than proof of the native G0 property's unit. The factory also explicitly sets `PreserveShapeOption=true`. A controlled probe with this option false produced a body while replacing the intended triangular start section with a reduced fitted outline: 9 expected edges became 6, and a corner was replaced by approximately (0.00005658, 1.30262417, 0) mm. This is a retained failure example, not acceptance evidence. The option's successful default-true sample preserved the tested triangle endpoints.

The intended product geometry domain is a single whole Sketch of active Line segments forming a connected polygon or open chain, with a path beginning at its unique profile vertex. Every active profile vertex's offset from that starting point must be perpendicular to the initial path tangent within 1e-6 mm. A single open Line alone does not uniquely determine a profile plane, so this is not a claim that the entire Sketch plane is normal to the path. The current validation error text says “profile plane must be normal”; that wording is stronger than the implemented vertex-offset check, which is the actual contract described here. The ordered path uses distinct independent Line/Arc curves with unambiguous endpoint continuity and tangent continuity. The native output preference is explicitly `solid` or `sheet`; no additional guide curve interface is claimed. Existing features whose definitions cannot be proven preserved are conservatively rejected. Product acceptance, source-association discovery, actual end-to-end rollback, and saved-copy reopening were subsequently assessed in the independent validation record cited above.

The product's requested `path_curve_ids` are ordered. Direction is determined from the Sketch origin and unambiguous endpoint continuity; native section elements must read back the same directed endpoints. The recommended sequence is independent spatial curves first, Sketches second, then sweeps. On a part that already contains Sketches, appending an F20 spatial curve can renumber existing Sketch-curve journal identifiers and be conservatively rolled back by F20's preservation checks. The F21 entry point accepts previously created conforming inputs and does not create a path inline; a successful prepared fixture is not evidence that every ordering of earlier operations is supported. An existing SKIN/Swept makes other modeling or edit writes conservatively unavailable because those operations do not all verify the existing Swept definition. F21 itself uses its separate strict preservation checks; inspection, ownership return and the strict SaveCopy path remain available.
