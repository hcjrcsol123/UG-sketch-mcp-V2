# F09 native sketch pattern and mirror acceptance

## Objective and boundary

Demonstrate the F09 linear, rectangular, circular, and named-sketch-axis mirror operations through the production `M2OpenModelAdapter`, with independently calculated geometry and direct NXOpen/UF readback. This acceptance applies to the recorded NX2506 millimetre configuration only. It does not establish reliability, manufacturing accuracy, regulatory compliance, or behavior on another NX release.

Traceability: `docs/V2.md` F09/T10, `docs/F09.md`, the frozen `M3SketchPatternRequest` contract, and the acceptance IDs below. F01–F08 remain previously accepted and are not rerun.

The expected `native_engine` is `NXOpen.CurveCollection.CreateLine/CreateArc + Sketch.AddGeometry(InferNoConstraints)` for linear, rectangular, and circular modes; these produce geometry-only copies without an associative pattern feature. Mirror remains `NXOpen.SketchMirrorPatternBuilder`. Acceptance records the operation's engine evidence and judges geometry from direct native sources and readback, never from the production preview.

## Configuration, setup, and safety

The designated operator runs the Journal only in one idle NX2506 session. The harness requires no active task environment, no active Sketch, and an original Work Part that is saved and unmodified. It creates a unique standalone millimetre part under `workspace/v2/models/`, binds only that part through the production adapter, and records the original Work Part identity for restoration. It does not start, restart, or terminate NX, overwrite the original part, or use an existing acceptance part. Each run uses a new model, round-trip model, and report path.

Run cases serially in that single NX session. Before each explicit `InspectPart`/`InspectSketch` materialization sequence, the harness saves the independent fixture. It records the returned `read_effects` beside the observed `Part.IsModified` values and does not save after those reads, so the following strict baseline contains the actual post-read dirty state. The harness captures a strict native snapshot and binding revision before every prepare, execution, verify, failure injection, and round-trip step. A `Prepare` rejection must leave the snapshot, modified state, and revision unchanged. A write outcome of `UNKNOWN` stops all subsequent writes and leaves the bridge write gate in its recorded safe state; no operation is replayed.

Instrumentation is the production adapter plus direct native NXOpen/UF enumeration of Sketch curves, Tags, point/axis/direction helper objects, constraints, frames, references, history, solver state, and bodies. No physical instrument is used, so instrument calibration is not applicable. CAD comparison tolerances are 1e-6 mm for positions, radii, and intrinsic curve lengths, and 1e-7 rad for arc extent, tangents, and frame orientation. These are numerical comparison limits, not metrology uncertainty. Record the actual NX modeling tolerance if it is looser; do not relax a failing comparison silently.

The harness records one native configuration run (`sample_size=1`). No reliability or population inference follows from it. Software protocol/STA fake tests, analytic helper tests, native subsystem validation, and installed MCP smoke are separate evidence layers; a passing layer does not substitute for another.

The adapter preview is captured as evidence but is never the geometry oracle. Matching is one-to-one: an actual curve cannot satisfy more than one expected instance, and missing/duplicate output is a failure.

## Evidence and reporting

`F09Acceptance.Main` writes one JSON report and retains the unique source and round-trip `.prt` models. The report contains UTC run/case IDs; source/round-trip/report paths; NX, NXOpen, bridge, adapter, and acceptance assembly versions; part units; sample size; tolerances; materialization read-effect records; source request; frame; direct before/after snapshots; production plan/execute/verify results; native Builder and helper Tag evidence; constraints, references, history, solver and body records; Save Copy/reopen results; and safety/cleanup state.

Every defect record contains the smallest reproduction setup, exact request/adapter call, expected numeric geometry and count, observed geometry and state, error code/exception, native call evidence, Undo outcome, and retest criterion. Retest uses a fresh unique model/report path, repeats the failed case plus its preservation checks and Save Copy/reopen check, and retains the original failure artifacts. Do not promote an exception to a pass unless the specified read-only rejection or actual verified Undo path is evidenced.

Offline compilation is `powershell -NoProfile -ExecutionPolicy Bypass -File tests/nx/v2/build-f09-acceptance.ps1`. The designated operator runs `tests/nx/v2/RunF09Acceptance.py` only after the build and NX session configuration are recorded. The acceptance Journal neither launches NX nor replaces loaded assemblies.
