# F07 NX Acceptance Plan

## Objective and limits

Validate F07 sketch-corner fillet and chamfer through the production `M2OpenModelAdapter` in NX2506. Prepare, execution, and verification must follow the production adapter path. An independent NXOpen readback will compare native sketch curves, endpoint topology, dimensions, constraints, and sketch ownership with values calculated from the requested geometry.

This is functional subsystem validation for the recorded NX build and part conditions. One run does not establish reliability, manufacturing accuracy, compliance, or behavior across other NX releases.

## Numerical oracle and angle definition

All sketch input and measured lengths are millimeters. Let `C` be the selected shared endpoint and let `e1` and `e2` be unit rays from `C` toward the retained far ends of curve1 and curve2. Let `θ = acos(e1·e2)`, constrained to `0 < θ < 180°`.

For a straight Line-Line corner fillet of radius `r`, expected trim distance is `t = r / tan(θ/2)`. The tangent points are `P1=C+t e1` and `P2=C+t e2`; the center is on the internal bisector at distance `r/sin(θ/2)` from `C`; the minor arc sweep is `π−θ` and arc length is `r(π−θ)`. The native circle must pass through both tangent points at radius `r`, and each native tangent must be parallel to its retained line. Line-Arc and Arc-Arc expectations use the respective independent circle-offset construction listed in the table.

For a chamfer with distances `d1,d2`, expected trim points are `A=C+d1 e1` and `B=C+d2 e2`; its length is `|A−B|`. For distance-angle mode, `δ` is measured at the first trim point A between `A→C` and `A→B`. Equivalently, δ is the angle between e1 and `B→A`; it is not the angle between e1 and `A→B`. Thus `d2=d1 sin(δ)/sin(θ+δ)`, with `0 < δ < 180°−θ`.

Fixed XY-plane reference values:

| Case | Expected native result |
| --- | --- |
| Right-angle fillet, `C=(20,0)`, retained rays west/north, `r=2` | `P1=(18,0)`, `P2=(20,2)`, center `(18,2)`, sweep `90°`, arc length `π mm`. |
| Right-angle equal chamfer, `d1=d2=3` | `A=(17,0)`, `B=(20,3)`, segment length `sqrt(18)=4.2426406871 mm`. |
| Right-angle two-distance chamfer, `d1=4,d2=2` | `A=(16,0)`, `B=(20,2)`, segment length `sqrt(20)=4.4721359550 mm`. |
| Right-angle distance-angle chamfer, `d1=4,δ=30°` | `A=(16,0)`, `B=(20,2.3094010768)`, segment length `8/sqrt(3)=4.6188021535 mm`; actual A-angle readback is 30°, and the native Asymmetric distance RHS values match `d1` and the independently derived `d2`. |
| Tilted non-axis 135° fillet, `C=(30,20)`, far points `(10,10)` and `(35,35)`, `r=1.5` | `t=0.6213203436 mm`; `P1=(29.4442741904,19.7221370952)`, `P2=(30.1964787442,20.5894362327)`; arc length `3π/8=1.1780972451 mm`. Apply the independently computed sketch frame to obtain expected world points. |
| Line-arc fillet, line `(10,2)→(10,9)`, arc center `(10,0)`, `R=2`, `90°→180°`, fillet `r=0.5` | Fillet center `(9.5,sqrt(6))`; line tangent point `(10,sqrt(6))`; arc tangent point `(9.6,1.9595917942)`; added arc radius `0.5 mm`. Remaining original arc must retain its far endpoint `(8,0)`. |
| Arc-arc fillet, original centers `(0,0)` and `(2,0)`, both radii `sqrt(2)`, shared `(1,1)`, fillet `r=0.25` | Fillet center `(1−sqrt(2)/4,sqrt(15)/4)`; direct tangent points are `(0.7852627661,1.1761642692)` on the first arc and `(0.8497788952,0.8227948772)` on the second; added arc radius `0.25 mm`; both original far endpoints remain. |

The distance-angle case checks the public semantic definition through an independent native-geometry measurement. The case passes only when the native Asymmetric builder record, stored distance RHS values, direct trimmed endpoints, and independently measured A-angle agree with the table. The separate NX OffsetAndAngle API probes remain diagnostic evidence and do not define the product's distance-angle semantics. A mismatch is recorded as a defect; the expected coordinates are not changed to fit an observed result.

For an equal-distance chamfer, NX uses only the `Distance1` expression in native `Symmetric` mode. Acceptance checks that mode and its active `Distance1` RHS, then independently measures both native trim lengths as the requested equal distance. The inactive `Distance2` expression is retained as diagnostic readback and is not an acceptance value. Unequal and distance-angle chamfers use `Asymmetric` mode, so acceptance checks both active distance RHS values.

## Classification, setup, and safety

Offline protocol and unit checks validate argument shape, units, ranges, exact-key rejection, endpoint selection, and the independent formula. CLR/STA tests validate prepare/execute/verify routing, stale revision handling, and rollback evidence using the test adapter. They are software verification, not NX evidence.

The real-NX acceptance is subsystem validation with a uniquely named millimeter test part. It uses production `M2OpenModelAdapter`, production prepare/execute/verify calls, and direct NXOpen geometry and constraint reads. The harness does not start NX. Only the designated NX operator runs `RunF07Acceptance.py` in the specified idle NX session. Do not run an external Journal and the M2 bridge against the same Work Part concurrently.

Before execution, compile the current production assemblies and F07 journal offline, then verify the operator's current NX process, Work Part, dirty state, and ownership. The harness requires NX outside a task environment and an empty or saved, unmodified original Work Part. It creates a unique test part and unique evidence paths under `workspace/v2/models` and `workspace/v2/evidence`; it never opens or changes the original part. It does not replace production DLLs, close a user part, or force-kill NX. On exit it releases its adapter binding and restores the original Work Part. Any failed restoration fails the run and remains in the report.

Before each seed sketch's strict prepare baseline, and before rejection/rollback baselines, the harness performs one explicit production `InspectPart` materialization read. It retains the full before/after native snapshots, binding revisions, and returned `read_effects`. The warm-up accepts only no model change or the declared `is_modified: false→true` transition when `read_may_mark_modified=true` and the reported flags agree; it does not save, undo, or clear that dirty state. The seed request then uses the current binding revision. Seed prepare and each rejection prepare are checked against fresh strict snapshots with no further state or revision difference. After another seed is created, earlier fixtures are re-inspected and their current JournalIdentifiers are resolved from the requested geometry before cross-sketch requests are built.

Raw NX `JournalIdentifier` values can repeat between sketches. Tests therefore resolve identifiers within the selected target sketch, and cross-sketch rejection uses a real connected Line pair in the foreign sketch whose current IDs are both absent from the current local ID set. Direct NX records retain each object's Tag and owning sketch so the evidence does not infer source ownership from a colliding identifier string.

Use NXOpen and UF readback. Read `Sketch.GetAllGeometry()` in full, record each native object, and separately count objects castable to `NXOpen.Curve`; fillet may create a `SketchVirtualPoint` helper object which is not a curve and must remain visible in the evidence. Enumerate every native constraint type with `Sketch.GetAllConstraintsOfType` and retain dimensional RHS/state and geometric operand associations; an empty adapter constraint summary cannot substitute for this independent readback. No external metrology is used. Therefore no physical instrument calibration applies. CAD comparison tolerances are `1e-6 mm` for points, radii, and lengths; `1e-7` for unit frame components; and `1e-7 rad` for angular comparisons. The harness records NXOpen/UF versions and assembly paths. These are numerical model tolerances, not manufacturing accuracy.

## Procedure and pass/fail criteria

1. Save a clean unique test part, take over through the production adapter, and record the binding revision, work-part inventory, `IsModified`, active sketch, curve IDs, and all sketch constraints.
2. Create a geometry-only right-angle sketch with two selected Lines and an unrelated third Line. Inspect the sketch to get current native `journal_id` values for both curves. Prepare a fillet for curve1=end and curve2=start with `r=2 mm`. Preparation must be read-only and explicitly identify the sketch, both IDs/endpoints, shared point, radius, and trim result. Execute and verify through production calls. Independently read the native trimmed lines and arc, then confirm tangent continuity, radius, one-sketch ownership, and the unrelated Line's unchanged Tag, type, owner, and endpoints. Record its before/after JournalIdentifiers diagnostically and re-read the current ID after the edit.
3. Create a second sketch on an independently defined tilted frame with non-axis-aligned lines `(10,10)→(30,20)` and `(30,20)→(35,35)`. Fillet curve1=end and curve2=start at `135°` using `r=1.5 mm`. Check the table's local points and independently transformed world coordinates against native readback. Verify the corner selection is not inferred from curve order.
4. On fresh fixtures repeat F07 for Line-Arc and Arc-Arc. Check the table's arc centers/radii/endpoints for the added and retained arcs; compare native start/end angles and lengths against the pre-operation snapshots; require the original far endpoints and sketch ownership to remain. This proves each supported curve pair after the production adapter's explicit endpoint mapping.
5. Use fresh sketches for equal-distance and unequal-distance chamfers. Verify both trimmed lines, new Line segment length and endpoints, absence of a new Driving dimension, endpoint topology, sketch ownership, and the unchanged unrelated line.
6. On another fresh right-angle sketch, exercise distance-angle mode with `d1=4 mm`, `δ=30°`. Record `requested_definition=distance_angle`, the derived `d2`, `native_mode=Asymmetric`, and both native distance RHS values. The current implementation maps distance-angle to an Asymmetric chamfer after calculating `d2` from the documented formula because NX2506's OffsetAndAngle HelpPoint behavior did not reliably preserve the selected first curve. Verify both trim points and the measured angle at A directly from NX curve endpoints. Fail if a different sign, complementary angle, or reversed curve order is silently accepted.
7. On fresh fixtures submit a unique missing ID, non-Line chamfer input, IDs from another sketch, same curve twice, mismatched/nonshared endpoints, and malformed numbers. Re-inspect both sketches after creating the foreign fixture. Require the cross-sketch pair's current foreign IDs to be absent from the local ID set, then submit those IDs with the local target `sketch_id` and require `CURVE_NOT_FOUND`. Every rejection must preserve the exact post-warm-up before/after model snapshots, active sketch, and binding revision. Do not infer a successful operation from a returned plan alone.
8. Submit an overlarge chamfer and a degenerate collinear corner as preflight-only refusals. For the overlarge fillet, accept either a preflight refusal with unchanged model/revision, or one native execution that returns `ROLLED_BACK` with native-call and Undo evidence, exact feature/sketch/body/curve/constraint/dirty/active-sketch restoration, a nondecreasing revision, and zero reported update errors. `APPLIED` or `UNKNOWN` fails; do not retry an unknown result.
9. Create a `geometry_only` right-angle sketch, add one native Driving horizontal projection dimension of 10 mm to the first Line through `Sketch.CreateDimension`, update, and independently read back solver status, degree-of-freedom count, Driving state, unit, RHS, and operand JournalIdentifier. Save and warm up the fixture before prepare. Success requires the existing Driving dimension's identity and semantic state to remain present after the corner edit; a rolled-back failure must restore the complete post-prepare baseline. The binding revision may advance monotonically during postcondition capture/Undo and is recorded; it must not decrease. If the revision advances, an unexecuted plan prepared before the native result must be rejected as stale without changing the restored model. Silent constraint removal or replacement is a failure.
10. Prepare two distinct corner plans against one revision. Execute one; require an advanced revision. Attempt the other stale plan and require direct-adapter `UNCHANGED` with `STALE_PLAN` or `STALE_REVISION`, and prove no native call or model change. Separately use `Line.SetStartPoint` on an existing geometry-only sketch Line under an invisible Undo mark, call `DoUpdate`, refresh inspect/session state, and prove semantic revision change while Tag, JournalIdentifier, feature/sketch/body inventory, and curve count stay fixed. The stale plan must remain rejected. Undo must restore exact endpoints, prior geometry verification, and the recorded pre-edit dirty state.
11. Save and reopen a production copy. Require `SAVED`, `reopened=true`, all production checks `VERIFIED`, and direct NXOpen reread of the successful native fillet/chamfer geometry and owning sketches.
12. Run the installed MCP representative smoke only after installation/load is recorded. Require installed version `0.7.0`, 23 discovered tools (21 existing plus 2 F07 tools), one applied and independently verified fillet, one applied and independently verified chamfer, successful save/reopen, and safe return of NX ownership to the human operator.

Every failed case captures its exact request, before/after model snapshot, production phase and result/error, native geometry/constraint readback, reproduction steps, and retest criterion. A preflight rejection is not reported as native rollback. Failure reports and any failed-state model are retained at unique paths; never overwrite a prior result. Retest after the defect is corrected by rebuilding current production assemblies and the acceptance DLL, then running all F07 cases on a new unique part/model path. Keep prior failed evidence for comparison.

## Evidence report

`F07Acceptance.dll` records one JSON report per unique run ID under `workspace/v2/evidence`. The report includes objective and requirement IDs, test class, timestamp, run result, NX and loaded assembly versions/paths, production adapter identity, units, tolerance, source and round-trip model paths, case input, independent expected values, direct native readings, constraint state, revisions, model snapshots, defects, reproduction and retest criteria, and session restoration state. The C# journal wrapper is compiled separately and the build script explicitly reports `nx_started=false`; a successful offline compile is not an NX result.

The report starts as `passed=false`, is persisted after each case, and becomes passed only if all required cases and session restoration pass. Preliminary native probes are retained at `workspace/v2/evidence/F07-native-probe-34362ece5d20462f92111becb8fd47ca.json` and the subsequent probe2/3/4 reports. They found that fillet adds `SketchVirtualPoint` helper geometry, `SketchVirtualPoint.GetParentCurves()` can trigger an NX fatal fault on stale objects, and native OffsetAndAngle HelpPoint behavior does not reliably preserve the selected curve order. Production code avoids the unsafe parent-curve lookup and maps distance-angle to the documented `d2` formula plus the native Asymmetric builder. The acceptance keeps the numeric oracle fixed and checks actual native endpoints. The final production acceptance passed; see the completed evidence below.

Test-only fixture generation does not claim the old two-line legacy_driving seed can be created.

The complete software suite passed 148/148, independent unit tests 31/31, previous NX regressions 96/96. Installed MCP `f07-mcp-installed-4.json` passed 6/6; three mutations were APPLIED and independently verified, SaveCopy/reopen checks VERIFIED, and ownership returned safely to HUMAN_OWNED.

JIDs are current identifiers resolved together with the explicit Sketch. The before-save baseline is captured immediately before saving. The save/reopen projection itself remains strict. Explicit read materialization records NX getter dirty effects before taking a strict baseline; it does not clear dirty state. All failed runs and their reports remain available.
